# 演習: 修正条件を伝え、AIの変更を確認する

[前の演習](01-start-and-scan.md)で確認した結果を使い、**修正条件をIssueにまとめ、変更を同じ検査で確かめること**が到達点です。操作は引き続き自分のCodespacesで行います。

## 1. 修正前のテストを実行する

検査用ターミナルで実行します。

```sh
python -m pytest -q
```

**完了の目印:** 初期版では引用符を含む正常な検索とSQL入力に対する2件が失敗し、71件が成功する。失敗名と理由を読み、前の演習で見た動作と照らし合わせます。

## 2. Issueに修正条件を書く

Copilot Chatに`semgrep-before.sarif`と`app/main.py`を指定し、自分で確認した検索結果とテスト結果を渡します。Chatで添付できれば追加します。検索候補に出ない場合は、次のようにファイル名を明記して読み取りを依頼します。

次のように下書きを依頼します。まだコードの修正は依頼しません。

```text
semgrep-before.sarifとapp/main.pyを読み、自分で確認した結果をもとに、
SQLインジェクションを修正するIssueの本文案を作ってください。
SARIFはruns[].resultsの指摘・位置・ruleIdを確認し、全ルールの説明は展開しないでください。
問題・影響・根拠・修正条件・作業範囲を簡潔にまとめてください。
実測と推測を分け、未実行の検査を成功と書かないでください。
他の2件は別の未対応課題として分け、コードはまだ変更しないでください。

自分で確認した検索・テスト結果：
（実行した入力と結果をここに貼る）
```

読み取れない・容量制限にかかる場合は、Viewerに表示されたSQLの指摘文・ルールID・ファイルと行番号を貼り付けます。SARIFの全ルール説明を貼る必要はありません。AIが使えない・下書きが1分程度で出ない場合は次の雛形を使います。

下書きを実測と照合し、次の条件が含まれるか確認します。維持したい正常動作を一つ自分の言葉で補い、GitHubの演習リポジトリの`Issues`から自分で投稿します。

```text
タイトル: 公開プラン検索で引用符を扱えず、未公開プランが表示される

再現したこと:
- 山梨は検索できる。
- O'Reillyを検索するとエラーになる。
- ' OR 1=1 -- を検索すると未公開プランまで表示される。
- Semgrepがapp/main.pyの、入力を埋め込むSQL文字列の組み立てを指摘する。

修正後に満たしたいこと:
- 公開プランだけを検索できる。
- 引用符を含む正当な検索が成功する。
- 日本語の部分一致と、%、_、バックスラッシュを文字として扱う仕様を維持する。
- 入力をSQLの構造として解釈させない。
- 既存の動作テストがすべて成功し、SemgrepのSQLインジェクションの指摘が0件になる。

変更時の条件:
- 対象はapp/main.pyの公開検索。作成・編集・共有機能を変更しない。
- テストの期待値や検査ルールを弱めない。
- 入力の一律禁止やエラーの握りつぶしで済ませない。
- 変更理由、実行した検査と結果、未確認の点を説明する。
```

**完了の目印:** 他の人が再現でき、修正完了を判断できるIssueになっている。

## 3. AIへ修正を依頼する

Codespaces内のCopilot Chatに、自分が作ったIssueのURLを渡して修正を依頼します。Copilotが`gh issue view`で本文を取得し、修正条件を確認します。

エディタ内の**Agentモード**を選び、次のように依頼します。GitHub上でIssueをCopilotに割り当てる操作ではありません。PR作成用のGitHub CLI（`gh`）は教材環境に含まれます。

```text
以下のIssueをgh issue viewで読み、条件を満たす修正をこのCodespacesで行ってください。
最初にgit statusと接続先を確認し、自分の演習リポジトリであることを確かめてください。
未コミットの変更があれば上書きせず停止してください。
mainからlessonブランチを作成してから修正してください。
lessonがすでにある場合は状態を確認し、勝手に削除・作り直しをしないでください。
テストとSemgrepを実行し、差分・実行結果・未確認事項を示してください。
この段階ではcommit・push・PR作成・mainへのマージはせず、私の確認を待ってください。

IssueのURL：
（自分が作ったIssueのURLを貼る）
```

コマンド実行の確認が出たら内容を読んで判断します。Issueを取得できない場合だけ、本文をChatへ貼り付けます。変更後は次の手順で自分でも差分と検査結果を確認してください。AIが使えない場合は`git switch -c lesson`でブランチを作り、[比較用修正案](04-fallback.md)へ進みます。

## 4. 変更を確認する

```sh
git diff
python -m pytest -q
semgrep scan --config p/owasp-top-ten --sarif-output semgrep-after.sarif app/
```

差分で、SQL文と入力値が別々に渡されているか、公開プランの条件が残っているかを確認します。テストやルールの削除、検査対象の除外で成功に変えていないかも確認します。

アプリをCtrl+Cで停止して`python scripts/start_app.py`で起動し直し、PORTSの5000番から前の演習の3種類の検索を再確認します。

**完了の目印:** テスト73件が成功し、SQLインジェクションの指摘がなくなる。全体検査では選択課題の2件が残る。画面でも引用符の検索が成功し、SQL入力で未公開プランが出ない。

Viewerで修正前のログを閉じ、`semgrep-after.sarif`だけを開いて残る2件を確認します。残る指摘は別の未対応課題として記録します。必須演習の完了はSQL修正の条件を満たしたことであり、アプリ全体を公開してよいという判断ではありません。

## 5. Copilotにコミット・PR作成を依頼する

自分の確認が終わったら、同じChatに`semgrep-after.sarif`と自分で確認したテスト・画面操作の結果を渡し、次を送ります。検査の失敗が残る場合は先へ進まず、原因を確認してください。

```text
差分と検査結果を確認しました。今回の修正をコミットし、PRを作成してください。
対象は自分の演習リポジトリだけです。配布元にはpushやPRを送らないでください。
現在のブランチがlessonであることと、commit対象の差分を確認してください。
必要な修正ファイルだけを明示して追加し、SARIFはcommitしないでください。
git push -u origin lessonで送信し、base=main、head=lessonのPRを作成してください。
mainへ直接pushしないでください。
PR本文にはIssue番号、変更理由、実行した検査と結果、残る2件の指摘、
未確認事項を書いてください。CIはまだ導入していないため未実行と記載してください。
認証や権限で失敗したら停止し、追加トークンや課金は要求しないでください。
作成したPRのURLを示し、マージはしないでください。
```

**完了の目印：** 自分のリポジトリにPRができ、対象ブランチ・差分・本文が実際の修正と一致する。Copilotの完了報告だけでなく、PRの画面を開いて確認します。

PR作成ができない場合は、次の手動手順で進めます。AIがすでにコミット・pushした場合は、その操作を繰り返す必要はありません。

### 手動で保存・PR作成する場合

```sh
git status --short
git add app/main.py
git diff --cached
git commit -m "Fix public trip search using SQL parameters"
git push -u origin HEAD
```

他のファイルも必要な理由があって変更した場合は、差分を読んで対象を明示して追加します。この教材ではSARIFを`.gitignore`で除外しています。commitせず、検査結果の要点をIssue・PRに記録します。

自分のリポジトリの`Pull requests`から`New pull request`を開き、base=`main`、compare=`lesson`でPRを作成します。Issue番号・変更理由・検証結果・残る指摘・未確認事項を書きます。配布元には送りません。

ここではマージせず、[CIの演習](03-ci.md)へ進みます。

## AIが使えない・処理が終わらない場合

後半10:54を目安に[講師の比較用修正案](04-fallback.md)に切り替えます。現在の差分を確認・保存し、作業中の変更を黙って上書きしないでください。講師の案も同じ検査・テスト・画面操作で確認し、PRに修正案の入手方法を書きます。未完了の場合は成功扱いせず、現状と次の作業を記録します。
