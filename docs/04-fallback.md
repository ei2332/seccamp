## AIの修正が間に合わない場合

後半10:54を目安に、次の講師による比較用修正案を使います。AIの生成結果ではありません。まず `git status --short` と `git diff` で途中の変更を確認・保存し、重なる場合は講師と相談してください。

`app/main.py` のSQL作成と実行を次のように変更します。周囲の例外処理、LIKEの文字の扱い、テストは変更しません。

```python
sql = "SELECT id, title, destination, body, visibility FROM trips WHERE visibility = 'public' AND title LIKE ? ESCAPE '\\' ORDER BY id"
try:
    trips = db.execute(sql, (f"%{term}%",)).fetchall()
```

`?`に入力値を別の引数として渡します。タプルのカンマを落とさないでください。引用符を禁止する方法では、正当な検索も使えなくなります。公開プランだけに限定する条件が残っていることも確認します。

```sh
git diff
python -m pytest -q
semgrep scan --config p/owasp-top-ten --sarif-output semgrep-after.sarif app/
```

期待結果はテスト73件成功、SQLインジェクションの指摘0件です。全体検査では選択課題の2件が残ります。ルール取得失敗や検査対象0件を成功と扱わないでください。

アプリを再起動し、画面でも確認します。

## Semgrepがルールを取得できない場合

通信・設定・対象を確認し、エラーを記録します。解決しなければ講師の実行結果で指摘とコードを照合します。テストが動く場合は実行します。PRには「Semgrep未実行：ルール取得失敗」など、未確認の範囲を明記します。

## CIが利用できない・待ち時間が長い場合

11:31を目安に講師の実行例でログを読みます。自分のPRのURL、対象コミット、現在の実行状態と次の操作を残してください。講師の結果を自分の結果として記録しません。

ローカル実行と講師ログの閲覧は学習の代替です。「自分のリポジトリでCIを確認した」という完了条件は未達として残し、後で自分のPRの最新コミットに対するpytest・semgrepの結果を確認します。

## 環境を起動できない場合

講師の画面とコードで仕様・問題を確認し、Issueの修正条件を考えます。環境の未起動と、実行していない検査を記録してください。ポートをPublicにして解決しようとしないでください。
# Trivyのミニ演習が進まない場合

導入・DB取得・検査が1分程度で終わらない、または容量不足の場合は[講師の比較結果](05-trivy.md#時間内に実行できない場合)で対象と結果を読みます。本人の検査は未完了と記録し、有料契約・環境の繰り返し作成・依存関係の一律更新は行いません。
