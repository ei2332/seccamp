# 選択課題：残る指摘を修正し、CIの検査範囲を広げる

必須演習が終わった人向けです。全体検査で残った2件をIssueに記録し、1件ずつ再現・修正・検証します。操作は自分の教材環境だけで行い、転送ポートはPrivateのままにしてください。

## 1. 印刷用の見出しを確認する

公開プランの詳細で「旅の準備・印刷」を開きます。「印刷用の見出し」に`<b>見出し確認</b>`と入力し、「印刷用のしおりを開く」を押します。

文字として表示したい入力が、HTMLの太字として解釈されます。`app/travel_tools.py`のHTML文字列の組み立てと、`app/templates/print.html`の`safe`を確認します。

SemgrepはXSSにつながるHTML生成を指摘します。このアプリにはCSPがあり、インラインスクリプトの実行を制限しています。**HTMLが混入することと、JavaScriptが実行できることは別**です。CSPを外して再現するのではなく、テンプレートの自動エスケープで入力を文字として扱うよう修正してください。

修正条件：通常の見出し・旅程を表示でき、入力したHTMLは文字として表示する。グループ限定・自分限定の閲覧制限とCSPを維持する。

## 2. ダウンロード先の範囲を確認する

「持ち物チェックリストをダウンロード」で通常動作を確認します。`app/travel_tools.py`では、`name`をファイルパスに結合しています。`../`で配布用フォルダの外を読めないか考えてください。

再現には下のテストを使います。一時フォルダに検証用の非公開メモを作るので、実際の個人情報・秘密情報やOSのファイルは使いません。

修正条件：配布用フォルダ内の資料だけをダウンロードできる。フォルダ外への指定や絶対パスを拒否し、存在しない資料は404にする。Flaskの`send_from_directory`等を検討し、利用条件を確認する。

## 3. テストと全体検査で確認する

```sh
python -m pytest -q exercises/extra_security_checks.py
python -m pytest -q
semgrep scan --config p/owasp-top-ten app/
```

選択課題のテストは明示したときだけ実行します。初期版では2件とも失敗します。通常テストは印刷やダウンロードの基本動作を確認しますが、この2つの攻撃入力は扱っていません。

2件とも修正したら、選択課題のテストと通常テストが成功し、全体検査の指摘が0件になることを確認します。新たな指摘や解析エラーが出た場合は内容を調べてください。

## 4. CIの合否判定を広げる

`.github/workflows/checks.yml`で次を変更し、PRで実行結果を確認します。

- pytestのコマンドを`python -m pytest -q tests/ exercises/extra_security_checks.py`にし、追加した修正条件も毎回確認する。
- `Report all OWASP findings`に`--error`を加え、全体検査の指摘でもCIを失敗させる。
- SQLインジェクション専用ステップは全体検査に含まれるため削除する。

指摘が消えたことだけで判断せず、再現した入力と通常動作の両方で確認します。CIの成功条件を広げたこともPRに記録してください。
